# Контракт Rush

Этот документ описывает текущий исполняемый Rush из `crates/tokenizer-rush`.
Грамматика редактора принимает некоторые конструкции, для которых исполнения
ещё нет; они перечислены в конце. Каталог встроенных функций и примеры находятся
в [README движка](../crates/tokenizer-rush/README.md).

## 1. Исходник и имена

- Файлы используют `.r`; идентификатор языка для редакторов — `rush`.
- Имена и ключевые слова чувствительны к регистру. `x` и `$x` — разные имена.
  `$` сам по себе недопустим. Лексер принимает буквы Unicode, `_` и префикс `$`,
  затем буквы, цифры и `_`; после `$` также допускается цифра.
- Комментарии: `//` до конца строки и невложенные `/* ... */`.
- Простой оператор заканчивается переводом строки или `;`. Внутри `()`, `[]`
  и записи `{key: value}` выражение может продолжаться на следующих строках.
  Перенос сразу после `return` завершает возврат без значения.
- Блоки записываются в `{ ... }` либо увеличением отступа пробелами. Перед блоком
  с отступами допустимо `:`. Табуляция в отступах запрещена.
- Форматтер выбирает фигурные блоки, четыре пробела, явные скобки вызовов и `;`.
  `const` нормализуется в `let`, `let mut` — в `mut`.

## 2. Значения и числа

Значения: конечные числа `f64`, строки, bool, null, списки, кортежи, записи,
функции, варианты Some/None/Ok/Err, математические/геометрические значения и
ленивые последовательности. Неявного преобразования строки в число или числа
в bool нет.

Числовые литералы десятичные, с необязательной дробной частью и экспонентой.
Отдельного целочисленного типа пока нет: запись целого числа не отменяет
округление `f64`. Деление на ноль, переполнение и другие нечисловые/бесконечные
арифметические результаты завершаются ошибкой. Сравнение чисел точное для их
представления `f64`; пользователь выбирает допуск для приблизительного сравнения.

Строки в одинарных или двойных кавычках декодируют escape-последовательности,
включая `\u{...}`. Unicode-нормализации нет. `len(string)` считает Unicode scalar
values, а не байты и не графемы. Индексы и диагностические spans исходника —
полуоткрытые диапазоны UTF-8 байтов. CLI показывает строки и столбцы с единицы;
столбец считается по Unicode scalar values.

Список `[1, 2]` и кортеж `(1, 2)` — разные типы. `(x)` группирует выражение,
`(x,)` создаёт одноэлементный кортеж, `()` — пустой. В позициях шаблона скобки
обозначают шаблон кортежа; форматтер явно добавляет запятую для одного элемента.

## 3. Области видимости и изменяемость

`let` и `const` создают неизменяемое имя. `mut` и `let mut` создают изменяемую
переменную. Инициализатор обязателен и вычисляется до появления нового имени.
Два объявления одного имени в одной области — ошибка; вложенная область может
его затенить. Параметры, имена функций и переменные `for` неизменяемы.

Имена разрешаются лексически в порядке объявлений. Функция захватывает значения
неизменяемых имён на момент создания, а изменяемые переменные — через общие ячейки
текущего исполнения. Изменения такой ячейки видны всем замыканиям, захватившим её.
Каждый `Program::run` создаёт новое состояние. Саморекурсия именованных функций
поддерживается; ссылки на будущие объявления и взаимная рекурсия не поддерживаются.

```rush
mut counter = 0
let next = () => counter += 1
(next(), next()) // (1, 2)
```

Присваивание исполняется только для имени `mut`: `=`, `+=`, `-=`, `*=`, `/=`, `%=`.
Оно возвращает присвоенное значение. При аннотации переменной контракт проверяется
и при инициализации, и при последующих присваиваниях. Запись через поле или индекс,
например `row.x = 2` или `xs[0] = 2`, пока отклоняется runtime даже для `mut`.

Деструктуризация поддерживает вложенные кортежи и записи. Размер кортежа должен
совпасть; запись должна содержать указанные поля и может иметь дополнительные.
`_` отбрасывает значение; повторные связанные имена недопустимы. Эти же правила
действуют в параметрах: `((x, y)) => x + y` принимает один кортеж, `(x, y) => x + y`
принимает два аргумента.

## 4. Порядок вычисления и вызовы

Обычный вызов вычисляет сначала вызываемое выражение, затем аргументы слева направо,
после этого проверяет контракт и выполняет функцию. Скобочная и командная формы
вызова дают одинаковый AST; скобочная форма предпочтительна для сложных аргументов.

`input | f(a) | g` вычисляет `input` один раз, затем `a`, вызывает `f(input, a)` и
передаёт результат в `g(result)`. Список остаётся одним аргументом. Каждая стадия
должна обозначать функцию или вызов; автоматического обхода элементов через pipe нет.

`and`/`&&` и `or`/`||` требуют bool и не вычисляют правую часть, если результат уже
известен. Условные выражения вычисляют только выбранную ветвь. Остальные бинарные
операторы вычисляют левый операнд перед правым. `assert` — обычный строгий вызов:
его необязательное сообщение тоже вычисляется до проверки условия.

Приоритет от низкого к высокому: присваивание, pipe, or, and, сравнения, `+ -`,
`* / %`, унарные `+ - ! not`, `**`, вызов/поле/индекс. Присваивание и `**`
ассоциируются вправо, остальные бинарные операции — влево. Например,
`-2 ** 2` означает `-(2 ** 2)`.

## 5. Результаты и управление потоком

Результат модуля — результат его последнего оператора:

| Последний оператор | Результат |
| --- | --- |
| Выражение | Значение выражения |
| Объявление переменной или деструктуризация | Значение инициализатора |
| Объявление функции | Значение функции |
| `if` с выбранной ветвью | Результат последнего оператора ветви |
| `if` без выбранной ветви | `null` |
| `while`, `for`, `import`, пустой модуль/блок | `null` |

Следовательно, `42; if false { 7 }` возвращает `null`, как и `42; import library`.
Результат предыдущего оператора не переносится через оператор без значения.

Именованная функция требует явного `return`, чтобы вернуть значение. Достижение
конца тела и `return` без выражения возвращают `null`, независимо от последних
выражений тела. Лямбда возвращает значение своего выражения. `return` проходит
через вложенные циклы/ветви; `break` и `continue` действуют на ближайший цикл.
Вложенная функция создаёт отдельный контекст управления потоком.

## 6. Доступ к данным, равенство и match

`row.field` и `row['field']` — строгий доступ к записи. Отсутствующее поле — ошибка.
`get` для записи, списка или кортежа возвращает Some/None. Числовые индексы списков,
кортежей и векторов начинаются с нуля; дробные, отрицательные и выходящие за границы
индексы отклоняются. У векторов также есть компоненты `.x`, `.y`, `.z`, `.w` в
пределах их размерности.

Равенство значений структурное; списки и кортежи разных типов не равны. Строки
сравниваются без Unicode-нормализации. Сравнивать функции и ленивые Sequence через
`==`/`!=` нельзя; это ошибка. Числовой Range сравнивается как описание диапазона.

`match` вычисляет значение один раз и пробует ветви по порядку. Поддерживаются
литералы, имена, `_`, вложенные tuple/record-шаблоны и Some/None/Ok/Err.
Связанные имена доступны только внутри своей ветви. Guard `if (condition)`
вычисляется после успешного сопоставления, должен вернуть bool; false продолжает
поиск. Отсутствие подходящей ветви — ошибка. Неограниченный guard'ом шаблон имени
или `_` должен быть последним. В выражении пустой Option создаётся как `None()`.

## 7. Коллекции и источники

`range(start, end[, step])` создаёт список; `range_iter` создаёт ленивое описание.
Конечная граница исключена, шаг по умолчанию 1, нулевой шаг запрещён. Точка с
индексом i вычисляется как `i * step + start` через fused multiply-add с одним
округлением, без промежуточного переполнения произведения. Если `f64`
не позволяет продвинуться к следующему числу, потребление завершается ошибкой.

`map` и `filter` выполняются сразу для списка и откладываются для последовательности.
`iter(list)` переводит уже существующий список в последовательность. `for`, `fold`,
`any`, `all` могут потреблять оба вида. `flat_map` пока собирает результат сразу.
`collect(sequence, maximum)` берёт не больше maximum результатов без дополнительного
чтения; при maximum = 0 источник не открывается и функции обработки не вызываются. Пустой fold возвращает
начальный аккумулятор; any([]) — false, all([]) — true.

Повторное потребление запускает последовательность заново и повторяет callbacks,
включая эффекты над захваченными `mut`. HostSequence каждый раз открывает новый
итератор; содержимое внешнего источника между открытиями может измениться.
При завершении, раннем выходе, ошибке, исчерпании бюджета или отмене итератор
освобождается через Drop. Хост отвечает за закрытие содержащегося в нём ресурса.

## 8. Типы, модули и приложение-хост

Поддержанные runtime-аннотации: `number`/`f64`/`float`, `str`/`string`, `bool`,
`null`, `angle`, `vec2`/`vec3`/`vec4`, `mat4`, `quat`, `polygon`, `mesh`, `sequence`,
`list[T]`, `tuple[T, ...]`, `Option[T]`, `Result[T, E]`. Аннотация параметра
проверяет весь аргумент перед деструктуризацией. Произвольные имена типов могут
разбираться грамматикой, но неизвестная runtime-аннотация — ошибка.

`analyze_calls` проверяет неизвестные аннотации и заведомо несовместимые типы
инициализаторов, явных `return` и аргументов пользовательских функций.
Аннотации параметров доступны внутри тела, включая вложенные tuple-шаблоны.
Контракты функций сохраняются через неизменяемые алиасы и destructuring
литералов кортежей/записей. Известный результат функции участвует в дальнейшем
анализе вызовов, pipe и компонентов вектора. Неизвестные типы не отклоняются;
Полнота возврата проверяется для известных контрактов; общий вывод типов остаётся ограниченным.
`Program::compile` выполняет этот анализ до исполнения, включая тела функций,
невыбранные ветви и обе стороны логических операций. Заведомо несовместимые
операнды арифметики отклоняются: числа поддерживают арифметические операции,
строки — сложение; векторы, углы, матрицы и кватернионы сохраняют свои правила.
Неизвестные значения хоста и динамические типы пока не требуют доказательства
совместимости при загрузке: это частичная проверка, а не полная система типов.
Runtime-проверки продолжают действовать независимо от статического анализа.

Для известных записей анализ проверяет имена полей и обязательные поля
record-шаблона. Для известных кортежей проверяется форма и длина вложенных
шаблонов, в том числе совместимость шаблона параметра с его аннотацией.
Условия `if`, `while`, guards у `match` и операнды логических операторов
должны иметь boolean-тип. Статическая проверка рассматривает обе стороны
логических операторов; runtime сохраняет короткое замыкание.



Модули регистрируются хостом явно по имени. `import` не ищет файлы и пакеты
самостоятельно. Модуль должен вернуть запись экспортов; она кэшируется в пределах
одного исполнения. Неизвестные имена модулей, дублирующая регистрация и циклы
импорта отклоняются. Каждое новое исполнение повторяет инициализацию модулей.

HostFunction задаёт контракт аргументов и результата, проверяемый runtime.

`HostRegistration::new` позволяет зарегистрировать callback с захваченным
состоянием приложения, например `Rc<RefCell<Scene>>`. Поле `function` содержит
тот же `HostFunction`, который передаётся анализатору; отдельного описания
сигнатуры для редактора не требуется. Callback проверяется на входе и выходе
по этой сигнатуре. Отмена проверяется повторно после возврата callback.

`Program::instantiate` создаёт `ScriptInstance` с собственными переменными и
кешем модулей. `call(name, arguments, limits)` вызывает именованную функцию
с новым бюджетом, сохраняя состояние между вызовами. Ошибка не откатывает
уже выполненные изменения. Исходник и cancellation token должны жить дольше
экземпляра; отменённый token продолжает запрещать следующие вызовы.
Экземпляр удерживает захваченное состояние host callbacks после удаления
исходных регистраций. Удаление экземпляра освобождает его ссылки на callbacks;
ошибка инициализации также освобождает эти ссылки. Сам дескриптор `HostFunction`
не удерживает контекст: вынесенный из экземпляра дескриптор без регистрации
не может вызвать прежнее состояние приложения.
Эти границы проверяются в `tests/instances.rs`.
Тот же набор тестов проверяет ленивый импорт внутри функции: модуль
инициализируется при первом вызове, затем использует кеш этого экземпляра.
Два экземпляра одной программы получают независимые переменные модуля.
Ошибка экспортированной функции сохраняет имя модуля и диапазон в его
исходнике; следующий вызов функции главного скрипта снова сообщает его
собственный диапазон без имени модуля. Изменения переменных, выполненные
до ошибки, сохраняются; повторная инициализация модуля не происходит.
`analyze_host_calls` использует ту же регистрацию для арности и известных типов
выражений; неизвестный тип не считается статической ошибкой. Анализ никогда не
вызывает callbacks. `analyze_names` проверяет имена по явно переданному окружению;
обычный парсер не обязан знать имена приложения-хоста.

Непрозрачный HostObject хранит слабую ссылку на объект приложения и имя его типа.
Алиасы сравниваются по идентичности и типу, включая ссылки на уже удалённый объект.
Последний сильный Rust-владелец определяет время жизни. Ссылка скрипта не удерживает
объект; аргументы и результаты host-функций с истёкшей ссылкой отклоняются runtime.
Хост может получить сильную ссылку через upgrade и удерживать её до конца операции.
Имена типов таких объектов задаются в регистрации хоста, а не аннотациями скрипта.

Математика и геометрия возвращают обычные значения. Приложение-хост решает, как их
показывать. В playground токенизатора нет 3D-просмотрщика.

## 9. Ошибки и пределы

Синтаксические ошибки препятствуют компиляции Program. Неизвестное имя при
исполнении, неподходящий аргумент, отсутствие поля, нечисловой результат, нарушение
аннотации, исчерпание бюджета и отмена возвращаются как RuntimeError с исходным
span и именем модуля, когда оно известно. Err(...) — отдельное обычное значение,
а не механизм перехвата RuntimeError.

Бюджет общий для выражений, вызовов и учитываемых операций с коллекциями/строками.
По умолчанию глубина вычисления ограничена 64; `run_with_limits` позволяет хосту
понизить её независимо от бюджета шагов. Значения выше 64 отклоняются. Глубина
учитывает выражения, тела функций и импорты. Отмена кооперативная: проверки стоят в runtime
и на границах host-операций. Native callback/open/read/Drop не прерываются принудительно.
Бюджет не является общим лимитом памяти, байтов хоста или времени блокирующего I/O.

Корутины с `yield` запускаются через API хоста, описанный ниже. Запись в поле/индекс
разбирается, но не исполняется. `async` и `await` зарезервированы. Полный вывод типов
и общий лимит памяти ещё не реализованы.

### Неявный результат именованной функции

При достижении конца тела именованная функция возвращает `null`; последнее
выражение не заменяет `return`. Анализ вызовов сообщает `missing-return`, если
аннотация результата запрещает `null` и структурный анализ обнаруживает путь
до конца тела. Проверяются ветви `if`, включая буквальные `true`/`false`, и
последующие операторы. Возвраты вложенных функций не учитываются.
Циклы `for` и `while` с небуквальным условием допускают ноль итераций.
Из `while true` можно дойти до следующего оператора только через достижимый
`break` этого цикла. `break` вложенного цикла не завершает внешний;
операторы после `return` или `continue` не создают новых путей выхода.
Это структурный анализ без доказательства значений произвольных выражений;
проверка аннотации при исполнении остаётся обязательной.

### Статическая проверка индексации

Для известных списков, кортежей и векторов анализатор требует числовой индекс.
Числовой литерал, в том числе с унарным знаком, должен быть конечным неотрицательным
целым; при известной длине проверяется верхняя граница. Для известной записи
индекс должен быть строкой. Значения других известных типов не индексируются.
Тип элемента аннотированного списка или вектора сохраняется при индексации;
для кортежа и литерала списка он определяется при известном индексе.
При строковом литерале-индексе известной записи сохраняется форма выбранного
поля, включая вложенные записи и компоненты векторов. Например, после
`let camera = config["camera"]` дополнения для `camera.position.` совпадают
с доступом через точку, если известна форма `config.camera`. Строковый ключ
декодируется теми же правилами escape, что при исполнении. Отсутствующий
литеральный ключ получает `unknown-record-field` на диапазоне индекса.
Для вычисляемого ключа и записи с неизвестной текущей формой поля не предполагаются.
Неизвестные значения и границы остаются предметом проверки при исполнении.

### Дополнение полей выражения

`analyze_editor_details` возвращает поля получателя каждого обращения через точку
и байтовый диапазон имени поля. Получателем может быть имя, вызов функции,
выражение в скобках, индексация или вложенная цепочка. Известная аннотация
результата функции и форма литерала учитываются без исполнения пользовательского
кода: `point().`, `[vec3(1,2,3)][0].` и `config["camera"].` получают соответствующие
подсказки. Затенённые builtins разрешаются по лексическому окружению; для
неизвестной формы список пуст. Playground использует эти диапазоны из AST.

Прежний `analyze_editor` сохраняет результат из трёх элементов. В расширенном
API недописанное последнее имя после точки может дать подсказки, но программа
остаётся синтаксически невалидной. Другие синтаксические ошибки подавляют
редакторские метаданные. Для именованных функций без аннотации анализатор собирает типы `return` и
учитывает `null`, если возможно завершение без возврата. Известные результаты
используются в подсказках и проверках; рекурсивные и динамические результаты
могут оставаться неизвестными. Все известные результаты `if` и `match`
проверяются на совместимость с ожидаемым типом.

`analyze_editor_with_host` также возвращает `member_completions`, используя
те же `HostFunction` и `ValueType`, что исполнитель. Поэтому зарегистрированный
результат `vec3` даёт оси после `point().`, а результат `mesh` — поля после
`model().` и оси после `model().vertices[0].`. Callback не вызывается при
анализе. Локальные функции и aliases разрешаются лексически. Для недописанного
последнего поля сохраняется `expected-name`; проверка арности вызова продолжает
работать, но лишняя ошибка неизвестного пустого поля не добавляется.

Из математических функций `normalize` сохраняет известную размерность вектора,
а `lerp` сохраняет общий известный числовой или векторный тип первых двух
аргументов. `cross`, `transform_point` и `transform_direction` имеют результат
`vec3`. Эти сведения проходят через aliases и последовательные стадии pipe;
они используются для дополнения компонентов, аннотаций и проверки аргументов
хоста. Локальное затенение имени builtin учитывается. Для неизвестных аргументов
`normalize` и несовпадающих типов `lerp` результат остаётся неизвестным;
это не заменяет проверку корректности операции при исполнении.

Для известных типов аргументов статически проверяются и сами операции:

- `normalize` и `length` требуют вектор.
- `cross` требует два `vec3`.
- `dot` требует векторы одинаковой размерности.
- `lerp` требует два числа либо два вектора одинаковой размерности и числовой коэффициент.

Диагностика указывает на несовместимый аргумент, включая неявный первый аргумент
pipe. Для разных размерностей используется `vector-dimensions`, для неверного
типа — `argument-type`. Проверка работает через aliases, учитывает затенение
имён и пропускает неизвестные типы. Проверки значений, например ненулевой длины
для нормализации, остаются у исполнителя.

Преобразования также имеют статические контракты: `translation`/`scaling`
принимают `vec3`; `transform_point`/`transform_direction` — `mat4` и `vec3`;
`rotation_matrix` — `quat`; `slerp` — два `quat` и числовой коэффициент;
`transform` — `mesh` и `mat4`; `translate` — `polygon` и `vec2`.
Для `axis_angle` ось должна быть `vec3`. Угол в `axis_angle`, `rotation_x/y/z`
и `rotate` может быть числом в радианах или значением `angle`.
`degrees` и `radians` принимают число и возвращают `angle`.

Результаты конструкторов матриц, кватернионов, полигонов и mesh сохраняют свой
тип в aliases и pipe. Это позволяет проверять аннотации и host-аргументы,
а также предлагать `vertices`/`triangles` после создания и преобразования mesh.
Геометрические ограничения и диапазон коэффициента slerp проверяются при
исполнении; неизвестные статические типы не считаются ошибкой сами по себе.

При композиции `mat4 * mat4` и `quat * quat` сохраняется соответствующий тип.
Для углов сохраняется `angle` при сложении/вычитании двух углов, умножении
на число с любой стороны и делении угла на число. Эти результаты доступны
проверкам аннотаций и host-аргументов после присваивания или передачи через pipe.
Недопустимые арифметические сочетания известных типов матрицы, кватерниона
или угла получают `math-operands` на диапазоне выражения. Например,
`identity()+identity()` и `degrees(90)*degrees(30)` отклоняются статически.
Сравнения на равенство сохраняют прежнюю семантику; неизвестные типы
оставляются для проверки при исполнении.
Операторы `<`, `>`, `<=`, `>=` принимают только числа. Каждый заведомо
нечисловой операнд получает `comparison-operand` на своём диапазоне;
это также работает, когда тип второго операнда ещё неизвестен.
Унарные `+` и `-` принимают число или вектор. Известный несовместимый тип
получает `unary-operand` на диапазоне операнда; неизвестные параметры функций
проверяются при исполнении. Углы, матрицы и кватернионы унарный знак не поддерживают.

### Контракты callback

Встроенные `map`, `filter`, `flat_map`, `any`, `all`, `group_by` вызывают callback
с одним аргументом; `fold` — с двумя. В `fold_by` функция ключа получает один
аргумент, reducer — два. `grid_mesh` передаёт два аргумента функции поверхности.
Эти контракты описаны в `Builtin::callback_arities` для runtime и анализатора.
Неверная арность известной функции отклоняется при вызове операции, в том числе
на пустом входе и при создании ленивой последовательности, до открытия источника.

Статическая диагностика `callback-argument-count` проверяет прямые вызовы
встроенных функций и pipe, включая известные алиасы передаваемых callback.
Неизменяемые алиасы встроенных операций, цепочки таких алиасов и destructuring
литералов кортежей/записей сохраняют контракт. Изменяемые переменные не получают
предполагаемый контракт из начального значения.
Пользовательские функции, затеняющие встроенные имена, не наследуют эти правила.

### Вложенные записи в анализаторе

Для литералов записей с именованными ключами анализатор сохраняет известные
типы значений полей, включая вложенные записи, списки, кортежи и векторы.
Неизменяемое имя или алиас вложенной записи сохраняет эту информацию.
Это позволяет проверять цепочки полей и использование их значений в аннотациях:
например, `config.camera.position.w` ошибочно, если `position` — известный `vec3`.
Повторяющийся ключ получает тип последнего значения, как при исполнении.
Динамические ключи, изменяемые записи и неизвестные параметры функций этим
правилом не уточняются. Completion поддерживает цепочки известных именованных полей, включая вложенные
компоненты векторов и пробелы вокруг точек. Индексация и результаты вызовов
внутри цепочки пока не поддерживаются. Метаданные `memberPaths` описывают поля
относительно корневого binding; затенение выбирает ближайшее видимое имя.

Известное значение данных нельзя вызывать как функцию: анализатор выдаёт
`not-callable` для чисел, строк, коллекций, записей и других известных типов
значений. При передаче такого значения в позицию callback встроенной операции
выдаётся `callback-type`, включая пустой вход. Неизвестные параметры и значения
функций не отклоняются по предположению; соответствующая проверка остаётся
в runtime. Поля записей, содержащие функции, сохраняют возможность вызова.

### Статические поля mesh

Значение mesh предоставляет `vertices: list[vec3]` и
`triangles: list[list[number]]`. Анализатор проверяет эти имена для известных
значений mesh, включая аннотированные параметры, и сохраняет типы элементов
после индексации. Например, `m.vertices[0].w` диагностируется как обращение к
несуществующей компоненте vec3. Неизвестные поля получают код `mesh-field`.
Подсказки редактора включают vertices и triangles; эти поля также доступны
через известную запись с вложенным mesh.

### Известная структура неизменяемых коллекций

Анализатор сохраняет структуру литеральных списков и кортежей через неизменяемые
переменные и aliases. Это позволяет проверить постоянный индекс по известной
длине, вывести тип выбранного элемента и сохранить поля вложенной записи после
деструктуризации кортежа. Например, в `let pair = ({x:1}, 0); let (item, _) = pair`
для item известен ключ x. Для изменяемых переменных структура начального
значения не используется как неизменная гарантия.

Проверка pattern рекурсивна: для известной записи проверяется наличие каждого
выбранного ключа, для кортежа — его вид и длина, затем вложенные patterns.
Неизвестная структура параметра не считается ошибкой. При деструктуризации
значения типа `tuple[...]` типы элементов передаются новым именам, в том числе
при вложенной деструктуризации. Проверки редактора и WASM используют тот же
анализатор, что и Rust API.

В цикле `for` переменная получает тип элемента аннотированного `list[T]`.
Для известного литерального списка структура элемента сохраняется, если она
одинакова у всех элементов. Это даёт диагностику полей и подсказки внутри
цикла, включая вложенные записи и векторы. Например,
`for point in [vec2(1,2)] { point.z }` получает `vector-component`.
Пустой список, элементы разной структуры и неизвестный источник не дают
такого уточнения. Источник разрешается до объявления переменной цикла;
после цикла снова видно внешнее имя, если оно было затенено.

### Бюджет сборки циклических ячеек

Обход графа изменяемых ячеек использует тот же бюджет шагов, что и выражения
Rush. Если бюджет исчерпан, исполнение возвращает `Execution limit exceeded`
с позицией инициализатора `mut`, который запустил обход. Частично построенный
граф не применяется: значения освобождаются при завершении исполнения.
Подготовленная `Program` остаётся пригодной для нового запуска с новым бюджетом.
Тесты `cell_lifetime.rs` отдельно проверяют ошибку внутри сборки, освобождение
удерживаемого значения хоста и успешный повторный запуск той же программы.

### Состав захвата замыкания

Функции и lambda сохраняют только внешние имена, используемые их телом,
включая имена, нужные вложенным функциям. Локальные объявления и параметры
разрешаются по лексическим ссылкам анализатора; одноимённая внешняя переменная
не захватывается, если все обращения относятся к локальному имени.
Неизменяемые значения сохраняются как снимки, изменяемые — как общие ячейки.
Неиспользуемые значения окружающего блока не удерживаются замыканием.

Подготовленная программа сохраняет информацию о ссылках исходника; замыкание
сохраняет доступ к этой информации для создания вложенных замыканий. При вызове
функции из модуля или из переданной хостом последовательности используется её
исходник, даже если позиции имён совпадают с позициями в вызывающей программе.

Ячейки `mut` принадлежат одному исполнению `run`. Если хост переносит
последовательность с таким захватом в другое исполнение, чтение или присваивание
возвращает `Mutable capture belongs to another execution`. Численно совпавший
индекс ячейки нового исполнения не используется. При присваивании владелец
проверяется до вычисления правой части. Перенос неизменяемых захватов допускается;
для изменяемого состояния между запусками приложение должно использовать
собственные объекты хоста.


## Пользовательские структуры и перечисления

Объявления типов находятся на уровне модуля и видимы в порядке исходника.
Названия встроенных типов и операций зарезервированы. Повторные имена полей,
вариантов и пустые перечисления отклоняются.

```rush
struct Settings { enabled: bool, speed: number }
enum State { Idle, Moving(vec3) }
let settings = Settings({enabled: true, speed: 3})
let state: State = State.Moving(vec3(1, 2, 3))
let speed = match state {
    State.Idle() => 0,
    State.Moving(velocity) => velocity.x
}
```

Конструктор структуры принимает ровно одну запись с полным набором объявленных
полей; лишние, отсутствующие и несовместимые поля отклоняются. Поля читаются
через точку, записи в них пока нет. Конструкторы вариантов вызываются через
пространство имён перечисления, в том числе для вариантов без данных: `State.Idle()`.
Параметры вариантов позиционные и типизированные. Неизменяемые алиасы
конструкторов сохраняют их контракты. Аннотации пользовательских типов работают
в параметрах, результатах и вложенных `list`, `tuple`, `Option`, `Result`.

Структуры и перечисления номинальны: обычная запись не соответствует структуре,
а одинаковые поля или варианты разных объявлений не делают типы равными.
Исполнение различает одноимённые объявления в разных зарегистрированных модулях.
Структуры допускают record-шаблоны; варианты перечислений — шаблоны
`State.Moving(value)`. Данные шаблонов сохраняют объявленные типы.

Для известного перечисления, `bool`, аннотированных `Option` и `Result` проверка
при загрузке требует полного покрытия `match`. Guard не засчитывается как
полное покрытие. Вариант с ограничивающим шаблоном данных, например `Event.Value(0)`,
требует дополнительной покрывающей ветви. `_` или безусловное связанное имя
покрывают остаток. Для неизвестного динамического типа проверка отсутствия
совпадения остаётся runtime-ошибкой.

Форматирование сохраняет новые объявления. Дополнение полей структур и вариантов
перечислений использует те же определения, что статический анализ. Пользовательские
данные учитываются при обходе захваченных клеток и удерживаемых значений, а также
могут возвращаться через `call_values`; `StateValue` пока не сериализует их.


### Распространение ожидаемых ошибок через `?`

`?` — постфиксный оператор с приоритетом вызова/доступа к полю. Он вычисляет
операнд один раз. `Some(value)` и `Ok(value)` распаковываются; `None()` и `Err(error)`
досрочно возвращаются из ближайшей вызываемой функции. Последующие выражения,
операторы и итерации пропускаются, ресурсы покидаемых итераторов освобождаются.
Ранее выполненные изменения сохраняются.

```rush
fn increment(value: Result[number, str]) -> Result[number, str] {
    return Ok(value? + 1)
}
```

Функция обязана явно объявить результат `Option[T]` или `Result[T, E]`.
Для известных типов семейства должны совпадать; тип распространяемой ошибки
Result должен быть совместим с типом ошибки результата функции. Тип успешного
значения может меняться. Использование вне функции, внутри нетипизированной
лямбды или с заведомо несовместимым операндом отклоняется при загрузке, включая
неисполняемые ветви. Для неизвестного значения проверка операнда остаётся runtime.
Ошибки исполнения, отмена и исчерпание бюджета не превращаются в `Err`/`None`.


## Явные интерфейсы модулей

`export name, other` объявляет публичные имена, уже определённые на уровне модуля.
Экспорты из вложенных блоков, отсутствующие имена и дубли отклоняются. Остальные
имена приватны для импортирующего скрипта. `import library` создаёт пространство
имён `library`; чтение приватного имени — ошибка. Хост по-прежнему явно сопоставляет
имена с исходниками `.r`; автоматического поиска по файловой системе нет.

```rush
// library.r
let private_scale = 2
fn twice(value: number) -> number { return value * private_scale }
export twice
```

При завершении инициализации создаётся запись явно экспортированных значений.
Экспортированное изменяемое значение — снимок на этот момент; функции сохраняют
захваченные клетки и могут читать/менять дальнейшее состояние модуля. Запись
кэшируется на экземпляр. Для совместимости модуль без `export` по-прежнему может
вернуть запись экспортов последним выражением.

`instantiate` проверяет граф импортов до любых эффектов инициализации: неизвестные
модули, дубли регистраций и все циклы запрещены, включая импорты в невызванных
функциях и невыбранных ветвях. Для явных интерфейсов анализ проверяет существование
полей импортированного пространства имён, включая неизменяемые алиасы, до исполнения.
`analyze_editor_modules` использует те же интерфейсы для диагностики и дополнения.
Интерфейс содержит параметры и результаты функций, номинальную идентичность типов,
поля структур и варианты enum. Анализ проверяет вызовы, аргументы, результаты,
конструкторы и `match` через импорт, включая переэкспорты и неизменяемые алиасы.
Аннотации `model.Settings`, `list[model.Settings]` и `Option[model.State]`
разрешаются только через публичные типы импортированного модуля. Для отдельного
`Program::compile` неизвестный интерфейс откладывается до `validate_modules` /
`instantiate`; эти проверки завершаются до любых эффектов. Legacy-записи экспортов
сохраняют динамическую проверку.

## Кооперативные корутины

Хост регистрирует задачу через `ScriptInstance::spawn_coroutine(name, args, limits)`;
тело ещё не выполняется. `resume_coroutine(id, limits)` выполняет её до следующего
`yield value` или возврата. Результаты — `CoroutineState::Yielded(value)` и
`CoroutineState::Complete(value)`. Каждый шаг получает свежие лимиты исполнения.
Локальные переменные, захваты, позиции ветвей/циклов и открытые итераторы сохраняются.
Обычные функции по-прежнему требуют `return`; завершение без него даёт `null`.

Значение `yield` — непрозрачный для ядра запрос хосту. Например, перечисление
`Wait { Seconds(number), Event(str) }` позволяет хосту поставить таймер или подписку
на событие и возобновить задачу после пробуждения. Ядро не ждёт настенные часы,
не запускает потоки и не создаёт подписки автоматически. Данные события могут
передаваться обычному обработчику экземпляра перед возобновлением.

`cancel_coroutine(id)` отменяет только эту задачу и сразу освобождает её локальные
значения и итераторы. Выполненные мутации не откатываются. Завершённая, отменённая
или упавшая во время шага задача больше не возобновляется. ID не переиспользуется
и не совпадает между экземплярами. Некорректные лимиты не начинают шаг. Общий
cancellation token остаётся липким; следующий `spawn_coroutine` или `resume_coroutine` освобождает все
задачи и возвращает отмену. Удаление экземпляра также освобождает задачи.

Приостановка разрешена в теле запущенной функции и её вложенных ветвях/циклах.
Вложенный вызов обычной функции выполняется синхронно и не может пересечь `yield`:
в таком случае задача завершается ошибкой. Возобновление одного экземпляра
последовательно; хост может чередовать задачи. `?` возвращает из задачи обычный
`None`/`Err`, тогда как ошибки, отмена и исчерпание бюджета остаются ошибками API.
Сохранённые окружения и источники учитываются в retained-data budget; непрозрачные
ресурсы хоста и AST исключены, как и для обычных экземпляров.

Пример с детерминированным моделированием времени и события:
`cargo run -p themoretheless-tokenizer-rush --example coroutine_motion`.

### Дополнительные проверки при загрузке

Для скалярных, математических и пользовательских значений выводится тип `mut`
из инициализатора. Простое и составное присваивание должны сохранить его; runtime
также сохраняет этот контракт для значений, неизвестных анализатору. Регистрация
хостовых функций в `instantiate` запускает проверку их сигнатур для всех ветвей
до эффектов инициализации. Полный вывод типов неизвестных результатов функций,
внешних входов и динамических записей остаётся ограничением текущего анализатора.


## Полные контракты функций и редактор проекта

Анализ выводит типы параметров из однозначных операций, известных вызовов,
условий и ожидаемого результата. Возвраты дают предварительный контракт для
саморекурсии, после чего проверяются аргументы рекурсивных вызовов и все возвраты.
Выведенные контракты сохраняются в runtime: неверный аргумент из хоста отклоняется
до входа в тело функции. Лексическое затенение не переносит требования на внешний
параметр. Неоднозначные операции, например неизвестное значение, умноженное на число,
не выбирают произвольно между числом и вектором.

`Program::compile_strict` требует определённый контракт каждой именованной функции.
Для проекта `validate_strict_modules` выполняет это с зарегистрированными интерфейсами;
CLI: `rush --check main.r --strict --module model=model.r` или
`rush main.r --strict --module model=model.r`. Неизвестные параметры/результаты
получают `dynamic-contract`: нужно явно аннотировать границу. Явный результат,
не допускающий `null`, требует возврата по всем путям. Без аннотации несовместимые
возвраты, включая завершение без возврата, не образуют полного строгого контракта.
Экспортируемые функции явных модулей должны иметь полный контракт при проверке графа.
Обычный `compile` сохраняет динамическую совместимость для остальных функций.

Это не система обобщённых типов: параметр `fn identity(x) { return x }` в строгом
режиме требует аннотации, а контракты функций высшего порядка пока не выражаются
через `ValueType`. Неопределённая рекурсия также требует явного результата.

`analyze_editor_project` возвращает анализ каждого зарегистрированного `.r`.
`NameReference.definition_module` задаёт файл определения импортированной функции,
типа, поля или варианта; `None` означает текущий документ. Диапазоны — UTF-8 байты.
`import_completions` возвращает доступные имена модулей по префиксу.
Анализ проекта также проверяет граф импортов, включая мёртвые ветви:
`unknown-module`, `cyclic-import` и `duplicate-module` указывают на ошибки
регистрации/графа; общая зависимость нескольких модулей не считается циклом.
`rename_project_symbol` возвращает изменения по документам и повторно проверяет
полученный проект. Коллизии, неверные идентификаторы и захват ссылок отклоняются.
Номинальные поля переименовываются в объявлении, конструкторе, обращениях и шаблонах;
одноимённые поля других типов не затрагиваются. Динамические ключи записей не имеют
идентичности символа. В Playground `F2` открывает форму переименования для одного
документа; `F12` использует те же ссылки. Редактор проекта — API для приложения-хоста,
а не встроенный файловый менеджер Playground.

## Планировщик времени и событий

`CoroutineScheduler::new(&mut instance)` связывает планировщик с одним экземпляром.
Запросы скрипта используют обычный тип:

```rush
enum Wait { After(number), Event(str) }
fn task() -> number {
  yield Wait.After(0.25)
  yield Wait.Event("ready")
  return 1
}
```

`spawn` регистрирует готовую задачу без исполнения. `poll(now: Duration, limits)`
продвигает время монотонно и возобновляет готовые задачи по времени пробуждения,
затем по порядку создания. Каждая задача выполняет максимум один шаг за `poll`;
нулевая задержка ждёт следующего вызова и не вытесняет соседние задачи.
Лимиты применяются отдельно к каждому возобновлению. Ошибка задачи терминальна и
возвращается как `ScheduledState::Failed`, остальные готовые задачи продолжаются.
Неверное время или лимиты не продвигают выполнение. `next_deadline` помогает хосту
выбрать следующий момент пробуждения; сам планировщик не спит и не создаёт потоков.

`emit(name)` пробуждает всех текущих подписчиков в порядке создания. События не
буферизуются и не несут payload; данные можно передать обычному обработчику через
`instance_mut` перед `emit`. Таймеры отсчитываются от времени текущего `poll`,
события получают время последнего `poll`. Отмена задачи, её ошибка и удаление
планировщика удаляют подписки и закрывают сохранённые итераторы; мутации сохраняются.
Общая отмена липкая. Если отмена уже установлена перед `poll`, вызов возвращает
ошибку без шагов. При отмене во время шага этот шаг возвращается как `Failed`,
предыдущие результаты сохраняются в ответе, а оставшиеся задачи отменяются.
Ожидания и подписки принадлежат хосту и не входят в retained-data
budget скрипта. `Wait.After` отклоняет отрицательные, нечисловые и переполняющие
длительности; необработанный `yield` другого значения завершает задачу ошибкой.
