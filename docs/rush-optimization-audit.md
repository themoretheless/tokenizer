# Итоговая проверка Rush — 2026-10-02

Цель: оптимизировать рабочий Rush, сохранив запрошенные типы, проверки до
исполнения, модули, ожидаемые ошибки, редакторские операции и корутины.
Численный порог скорости в задаче не задан. Итог проверяется прямым сравнением
исходного и окончательного runtime, проверками поведения и сборкой потребителя.

## Результат производительности

Все шесть сценариев подготовленного runtime в итоговой последовательной серии
ускорились: closure 1.71×, collections 1.46×, collections_lazy 1.55×,
cells 1.08×, cells_cycles 1.14×, surface 1.53×. Загрузка plain — 1.90×,
host — 1.78×, цепочки 1/8/24 модулей — 2.25×/5.26×/10.26×.
Это результаты выбранных workload на Apple M4 Max, macOS aarch64.
Коэффициенты отдельных правок не перемножаются, скорость WASM не заявляется.

[Загрузка: полные выборки, диапазоны и SHA-256](benchmarks/rush-final-loading-2026-10-02.json).
[Отдельные проверки корутин](benchmarks/rush-coroutine-2026-10-02.json).
[Методика, память, профили и отклонённые варианты](rush-performance.md).

Сохранены повторное использование интерфейсов/контрактов при загрузке,
остановка вывода типов на неподвижной точке, общий AST кадров корутин,
подготовка стека ошибок только при ошибке, точный целочисленный путь `%`
и compound assignment без временной копии AST. Два варианта резервирования
кадров удалены после обнаружения замедления; ранние варианты общей
арифметической функции заменены проверенным вариантом без отдельного вызова.

## Соответствие запрошенному поведению

| Требование | Рабочая реализация и проверка |
| --- | --- |
| struct, enum, поля, исчерпывающий match | Номинальные типы и конструкторы; [user_types](../crates/tokenizer-rush/tests/user_types.rs) проверяет неверные поля/варианты и неполные/условные шаблоны в мёртвых ветвях |
| Типы до исполнения | Program::compile проверяет известные типы; [load_types](../crates/tokenizer-rush/tests/load_types.rs) отклоняет невызванные функции, мёртвые ветви, неверные аргументы/возвраты и присваивания |
| Option, Result, ? | Успех извлекается, ошибка возвращается из ближайшей функции; [try_operator](../crates/tokenizer-rush/tests/try_operator.rs) проверяет остановку дальнейших эффектов и совместимость результата |
| Модули, экспорты, приватность, циклы | Graph preflight до инициализации; [modules](../crates/tokenizer-rush/tests/modules.rs) проверяет приватные имена, экспорты, отсутствующие/циклические импорты в мёртвом коде |
| Состояние, возобновление, отмена корутин | Сохраняемые кадры и терминальная отмена; [coroutines](../crates/tokenizer-rush/tests/coroutines.rs) проверяет локальные значения, циклы, break/continue, ошибки и лимиты |
| Форматирование, навигация, rename, completion, диагностика | Общий анализ языка; [user_types](../crates/tokenizer-rush/tests/user_types.rs), [project_editor](../crates/tokenizer-rush/tests/project_editor.rs), Playground tests; граф редактора проверяет те же нарушения регистрации, что загрузчик |
| Межмодульные сигнатуры и model.Settings | [module_contracts](../crates/tokenizer-rush/tests/module_contracts.rs) проверяет импортированные вызовы до эффектов, квалифицированные/вложенные типы, переэкспорты и замену библиотеки под тем же именем |
| Вывод контрактов, рекурсия, все возвраты, аннотации границ | compile_strict / validate_strict_modules / CLI --strict; [module_contracts](../crates/tokenizer-rush/tests/module_contracts.rs) проверяет саморекурсию, несовместимые аргументы/возвраты и неоднозначные границы; [cli](../crates/tokenizer-rush/tests/cli.rs) проверяет режим --strict |
| Rename полей/вариантов, переходы между .r, импорты | analyze_editor_project, definition_module, rename_project_symbol, import_completions; [project_editor](../crates/tokenizer-rush/tests/project_editor.rs) проверяет адреса документов, точные правки, коллизии, алиасы и граф; Playground предоставляет F2 для текущего документа |
| Единый планировщик времени/событий | CoroutineScheduler и Wait.After/Event; [scheduler](../crates/tokenizer-rush/tests/scheduler.rs) проверяет порядок, справедливость нулевых задержек, broadcast, отмену и освобождение подписок |

Границы API сохранены: модули регистрирует хост/CLI, время и события передаёт
хост, редактор проекта возвращает анализ/правки по документам. Строгие
контракты включаются соответствующим API или --strict, обычная компиляция
сохраняет динамическую совместимость. Ограничения обобщённых типов и
контрактов функций высшего порядка описаны в [спецификации](rush-language-spec.md).
Экспериментальные backend из исторических разделов performance-документа
не подменяют рабочий исполнитель и не используются для итоговых коэффициентов.
